=== PÁGINA 22 ===
1. Herramientas por Categoría y Lenguaje

Para que una inspección estática sea efectiva, no debe ser un evento único, sino un proceso continuo:
Nivel 1: El IDE (Local)
             Cómo:   Instalar extensiones (como la de SonarLint            o ESLint) directamente en VS Code          o PyCharm.
             Resultado:    El programador ve "subrayados" rojos o amarillos mientras escribe, corrigiendo errores
             antes de siquiera guardar el archivo.

Nivel 2: o Pre-commit   Hooks
             Cómo:   Usar una herramienta llamada pre-commit. Se configura un archivo .pre-commit-config.yaml.
             Resultado:    Cuando el desarrollador intenta hacer un git           commit, la herramienta corre
             automáticamente. Si hay errores (por ejemplo, una variable no usada o un fallo de seguridad), el
             commit    se bloquea hasta que se arregle.

Nivel 3: El Pipeline de CI/CD (Servidor)
             Cómo:   Configurar GitHub Actions, GitLab         CI o Jenkins para ejecutar las herramientas cada vez que
             alguien sube código o abre un Pull          Request.
             Resultado:    El equipo de revisión técnica recibe un reporte automático. Si el código no pasa los
             "Quality  Gates" (umbrales de calidad), no se permite la integración al proyecto principal.
