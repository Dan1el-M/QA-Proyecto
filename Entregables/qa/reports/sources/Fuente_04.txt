1. Contexto del laboratorio
En este laboratorio el estudiante deberá diseñar, ejecutar y documentar pruebas de integración para un flujo de
compra o consumo de servicios mediante APIs. El objetivo no es solo llamar endpoints, sino validar que varios
componentes trabajan correctamente: consulta de productos o servicios, creación de carrito, cálculo de total,
persistencia temporal, validación de contrato, manejo de errores y generación de métricas de calidad.

2. Objetivos de aprendizaje
•   Diseñar casos de prueba de integración a partir de un flujo funcional real.
•   Configurar y ejecutar pruebas de API en Postman utilizando variables, ambientes, scripts y aserciones.
•   Validar contratos de respuesta: estructura JSON, tipos de datos, códigos HTTP y reglas de negocio.
•   Automatizar pruebas de integración con Pytest usando una API pública y SQLite en memoria.
•   Definir métricas de calidad para evaluar estabilidad, cobertura, tiempos de respuesta y defectos
    encontrados.
•   Documentar evidencias de ejecución y conclusiones técnicas del proceso de pruebas.

3. Escenario base del laboratorio
Buscar un prohyecto  con un  un sistema o API donde exista un proceso similar al siguiente:

•   Consultar productos o servicios disponibles.
•   Seleccionar uno o varios productos o servicios.
•   Agregar elementos a un carrito, orden o solicitud.
•   Consultar el total calculado.
•   Ejecutar o simular el proceso final de compra/solicitud.
•   Validar que el sistema responda correctamente y que los datos se puedan persistir o registrar.

En esta parte se debe automatizar un flujo básico usando Python. Se consumirá una API pública, se validará la
respuesta y se almacenará información en SQLite en memoria como persistencia falsa. La base de datos debe
crearse y destruirse en cada prueba para garantizar aislamiento.

Ejercicio 9: Crear base de datos SQLite en memoria
import sqlite3
import pytest

@pytest.fixture
def db_connection():
    conn = sqlite3.connect(':memory:')
    cursor = conn.cursor()
    cursor.execute('''
        CREATE TABLE carrito (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            producto_id INTEGER NOT NULL,
            nombre TEXT NOT NULL,
            precio REAL NOT NULL,
            cantidad INTEGER NOT NULL,
            total REAL NOT NULL
        )
    ''')
    conn.commit()
    yield conn
    conn.close()
Ejercicio 10: Consultar API pública y validar contrato
import requests

BASE_URL = xxxx

def test_consultar_productos():
    response = requests.get(f'{BASE_URL}/products', timeout=10)
    assert response.status_code == 200
    products = response.json()
    assert isinstance(products, list)
    assert len(products) > 0
    product = products[0]
    assert 'id' in product
    assert 'title' in product
    assert 'price' in product
    assert isinstance(product['price'], (int, float))

12. Criterios de calidad esperados
•   No se aceptan pruebas que solo verifiquen status 200. Cada endpoint importante debe tener al menos tres
    validaciones.
•   Las credenciales reales no deben incluirse en capturas, repositorios ni archivos exportados.
•   Los datos de prueba deben ser claros y repetibles.
•   Las pruebas automatizadas deben poder ejecutarse desde cero sin configuración manual excesiva.
•   El reporte debe explicar qué se probó, qué falló, por qué es importante y qué se recomienda mejorar.
